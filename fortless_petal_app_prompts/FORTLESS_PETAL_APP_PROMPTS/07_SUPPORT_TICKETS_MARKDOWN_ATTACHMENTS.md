# Task 07: world-class support tickets with Markdown, files and staff workflow

**Existing:** `src/modules/support/tickets.ts` implements DB-backed create/list/thread/customer-reply; `public/assets/app-ui.js` has `loadTickets`, `openTicket`, `sendReply`, `createTicket`; `/admin` has newer staff ticket detail/reply/status logic. Refactor INCREMENTALLY without breaking current endpoints, old messages or staff permissions.

**Canonical Petal:** Communication > Multi-conversation inbox `.z-ci`, comments with tasks/mentions `.z-cmt`; Data > chat bubbles, file rows, quote, timeline; Advanced forms > Rich text editor `.rte`/`rte()`; Forms pro > Mentions editor `.z-ed`; Inputs > File upload `.drop`; Overlays > side drawer, modal, bottom sheet; Selection > badges/priority; Feedback > skeleton/error/upload progress; Data & tables > saved filters/bulk actions.

Implement coherent customer and staff ticket inboxes with canonical ticket IDs, status, priority, department, optional linked service, assigned staff, created/update time, unread count, filters/search/sort and direct `/app/support/:id` deep links. Staff queue: claim/reassign, internal notes, priority/escalation, status changes, canned replies, audit and ownership checks. Customer sees **no internal note** and cannot enumerate other tenant tickets.

Composer: markdown source + safe preview (reuse Petal rich text editing toolbar visuals; source/preview toggle if necessary), headings/links/code blocks/lists/quotes, keyboard shortcuts, local draft retention, mention picker only for authorized participants, paste/drop attachments, previews, remove-before-send, upload progress, and automatic feedback. Rendering MUST sanitize HTML and URLs and never trust raw contenteditable HTML. Rich text gallery demo uses `execCommand`; do not rely on raw unsanitized HTML in production. Preserve Markdown/plain-text schema consistently and provide migration/backwards-compatible rendering for existing messages.

Attachments: authenticated short-lived uploads/downloads, enforced size/count quotas, MIME allowlist plus signature validation, sanitized filenames, opaque storage identifiers, object-storage/private filesystem abstraction, access checks on both metadata and bytes, no public path traversal, quarantine/AV hook for risky file types, download content-disposition, CSP. Never permit executable SVG/HTML inline by default. Batch commit message + attachments atomically at DB metadata layer; document orphan cleanup/retries. Attachment lifecycle/retention/deletion and legal request support.

Notifications (email/in-app) only for real status and replies; do not leak staff-private messages. Test HTML/Markdown XSS, malicious links, unauthorized attachments, rapid double send, upload race, closed ticket, agent vs customer views, phone bottom sheet, and long threads/pagination. Add read receipts/attachments only where persistence is real.
